# Plan VI: Testnet v2 deploy, registry entry, bindings, integration suite

**Sprint goal:** Stellar contracts run on soroban-sdk 27 as versioned v2 deployments whose addresses every consumer resolves from contracts.json.
**Worktree:** false — sequential waves share `node_modules`, `target/` and `dist/` build caches on one checkout, and Plans VI/VII need the deployed registry state of that same checkout.
**This plan delivers:** the sdk-27 protocol contract deployed and initialised on testnet, registered as `testnet.v2` with `current` flipped to `v2` after the vitest integration suite passes against it, TypeScript bindings regenerated with stellar-cli 27.1.0, and the JS SDK moved to 16.x across the workspace.

## Tasks

### I. Deploy v2 to testnet and register it

- **Files:** `contracts/stellar/bindings/src/contracts.json` (written by `deploy.sh`), `contracts/stellar/deployments.json` (regenerated by `deploy.sh` via `scripts/sync-deployments.sh`; still points at v1 while `current` is v1)
- **Read first:** `contracts/stellar/deploy.sh` (whole file, as modified in Plan IV), `contracts/stellar/readme.txt` "Deploy to Testnet", CONTEXT.md D-01/D-21, `contracts/stellar/.gitignore` (env.sh entries)
- **Action:**
  1. Identity per D-21: if `contracts/stellar/env.sh` exists and sets `SOURCE_IDENTITY`, use it. Otherwise `stellar keys generate attest-v2-testnet --network testnet --fund` and use `--source attest-v2-testnet`. Record the identity name and its public key (`stellar keys address attest-v2-testnet`) in EXECUTION.md. Never print or commit the secret.
  2. From `contracts/stellar`: `./deploy.sh --protocol --version v2 --network testnet --rpc-url https://soroban-testnet.stellar.org --network-passphrase "Test SDF Network ; September 2015" --source <identity> --initialize --yes`. The script builds via `stellar contract build`, deploys, initialises with `--admin <identity address>`, and writes `testnet.v2` into `contracts.json` with `sdk: "27.0.6"`, `deployedAt`, `deployedLedger`, `txHash`, `wasmHash`. `testnet.current` must still read `v1` after this step.
  3. Verify on-chain: `stellar contract invoke --id $(jq -r .testnet.v2.id bindings/src/contracts.json) --network testnet --source <identity> -- get_dst_for_attestation` returns the DST bytes; `curl -s "https://stellar.expert/explorer/testnet/contract/<id>"` is reachable (informational).

- **Covers:** D-01, D-21, GOAL testnet deploy

- Backfill on the Railway instance runs only after the user applies the env and calls the endpoint (D-04, D-14).
